# dynamic-workflows-lab

你好！

Empirical companion to the blog post [Dynamic Workflows](https://xielixing.github.io/) —
two controlled experiments comparing **script orchestration** (Claude Code dynamic
workflows) against **natural-language orchestration** (Claude spawning subagents
turn-by-turn from the main thread).

## Experiments

| # | Task | Verification | Hypothesis |
|---|------|--------------|------------|
| 1 | Audit 24 TS files for a planted bug pattern (6 files affected) | Ground-truth list | Workflow wins on determinism (coverage/recall variance), per-agent context precision, and total tokens |
| 2 | Fix failing test suite across 3 modules, iterate until green | `npm test` exit code | Workflow still wins on a complex multi-round task; adversarial verification lowers "cheat rate" |

Both arms use the same model (single-model proxy setup), same fixture, fresh session
per run, n=5 per arm.

## Layout

```
fixtures-src/          # tracked source of truth for both fixtures
  exp1-audit/          # 24-file TS repo, 6 planted missing-await bugs
  exp2-fix/            # repo with failing tests + planted root causes
fixtures/              # generated by tools/gen-fixtures.mjs (gitignored, own git repo each)
tools/                 # generator, runner, transcript parser, graders
prompts/               # exact prompts per arm & experiment
grading/               # ground truth + cheat-pattern rules
results/               # per-run artifacts + aggregated metrics (raw transcripts gitignored)
```

## Reproduce

```bash
node tools/gen-fixtures.mjs        # generate fixtures + baseline commits
node tools/run-exp1.mjs            # runs 5x NL arm + 5x WF arm via `claude -p`
node tools/parse-transcripts.mjs   # token accounting from ~/.claude/projects
node tools/grade-exp1.mjs          # coverage / recall / precision / Jaccard
```

## Measurement notes

- Token counts come from `~/.claude/projects/<munged-cwd>/<session-uuid>.jsonl`
  (`message.usage`), split into main-thread vs subagent lines (`isSidechain`).
- Workflow telemetry lives under `<session-dir>/subagents/workflows/wf_*/`:
  per-agent transcripts, `journal.jsonl`, and `wf_*.json` (contains the exact
  generated script).
- Trigger path for the workflow arm: `ultracode:` keyword in `claude -p` (verified
  working on Claude Code v2.1.218; the docs' claim that `-p` never triggers
  workflows is outdated as of this version).

## Honesty policy

n=5 per arm, single machine, synthetic fixtures, one model behind a proxy.
This is engineering-grade evidence for a blog post, not a paper. Negative and
inconclusive results are reported as-is.

## MEASUREMENT CAVEAT (discovered 2026-09-02, interactive verification)

Claude Code transcripts **under-record subagent token usage** for BOTH arms:
- Workflow subagents: usage recorded for only 2–5 of 24 agents per run
  (all-or-nothing per agent). Agents that DO record average ~19.0k tokens
  (input ≈1.5k + cache_read ≈17.4k), matching the `/workflows` panel
  (~19.4k–22.7k per agent).
- Task subagents (NL arm): usage almost always 0.

Therefore the `meanGrandTokens` / `meanSubTokens` aggregates in
`results/*/summary.md` are **underestimates** and the unattended token
conclusions are **retracted** until re-measured. The `/workflows` panel is the
authoritative per-agent source. Determinism / success / cheat metrics are
content-based and unaffected. Interactive re-verification in progress:
see `results/interactive/run-log.md`.
