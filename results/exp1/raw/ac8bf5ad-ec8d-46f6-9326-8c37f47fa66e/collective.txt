# Consolidated Audit Report — Un-awaited Promise in Boolean Context

**Summary:** 6 files audited, 6 files with confirmed findings, 6 total findings, 6 confirmed, 0 false positives.

All six cases share the identical defect shape: an `async` helper returning `Promise<boolean>` whose result is stored in a `const` without `await` and consumed by an `if (!x)` guard. A Promise object is always truthy, so `!x` is always `false`, the guarded branch is permanently dead, and `await` after the `const` no longer helps — the await must be placed on the call itself.

## src/inventory/reservationService.ts
- **`reservationService.ts:15`** in `reserveForOrder` — `hasActiveReservation(orderId)` — `hasActiveReservation` is `async` (line 4), but `const already = hasActiveReservation(orderId)` stores a `Promise<boolean>` un-awaited and `if (!already)` (line 16) is therefore always false, making the reservation-insert branch dead: the second call hits `existing[0]` which is `undefined` for a first-time order, breaking the INV-118 idempotency contract and the `Promise<Reservation>` return type. Fix: `const already = await hasActiveReservation(orderId)`.

## src/notifications/digestBuilder.ts
- **`digestBuilder.ts:21`** in `buildDigestsFor` — `hasDigestBeenSent(id)` — the `async` `hasDigestBeenSent` is called without `await`, so `if (!sent)` (line 22) never fires; the digest-compose/insert branch is dead and *every* user, including those who already received one, gets a digest, silently inverting the CRM-204 duplicate-suppression intent. Fix: `const sent = await hasDigestBeenSent(id)`.

## src/orders/fulfillmentService.ts
- **`fulfillmentService.ts:26`** in `fulfillOrder` — `hasStock(item.sku, item.qty)` — `async hasStock`'s promise is stored un-awaited in `ok`, so `if (!ok)` (line 27) never throws `OutOfStockError` and shipments are created for out-of-stock items — the exact WMS-77 phantom-shipment scenario. Fix: `const ok = await hasStock(item.sku, item.qty)`.

## src/orders/returnsService.ts
- **`returnsService.ts:51`** in `autoApproveIfEligible` — `autoApprovalBlocked(orderId)` — the `async` `autoApprovalBlocked` is called without `await`, so `if (!blocked)` (line 52) is always false: the refund auto-approval branch is dead and `autoApproveIfEligible` always returns `false`, silently defeating the FIN-31 finance gate. Fix: `const blocked = await autoApprovalBlocked(orderId)`.

## src/pricing/promoCodes.ts
- **`promoCodes.ts:16`** in `applyPromo` — `promoIsStale(code)` — `async promoIsStale` is called un-awaited (call is line 16; the guard `if (!stale)` is the finding's cited line 17), so the discount branch is dead and `applyPromo` always returns the unchanged `totalCents`, silently negating the FIN-27 expired-promo gate. Fix: `const stale = await promoIsStale(code)`.

## src/users/authService.ts
- **`authService.ts:36`** in `assertCanManage` — `hasPermission(user, action)` — the `async hasPermission` promise is stored un-awaited in `allowed`, so `if (!allowed)` (line 37) is always false: `ForbiddenError` is never thrown and the SEC-12 authorization denial path is permanently dead. Fix: `const allowed = await hasPermission(user, action)`.
